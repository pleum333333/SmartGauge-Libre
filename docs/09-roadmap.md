# 09 · แผนพัฒนา (Roadmap)

รวบรวมจากการสำรวจสมาร์ทเกจ/OBD gauge ที่ขายในไทยและต่างประเทศ (Lufi XF, P10/P12/P17, UltraGauge, ScanGauge, AUTOOL X50 Pro, Torque Pro, Car Scanner ฯลฯ)
และโปรเจกต์โอเพนซอร์สบน GitHub — เป้าหมายคือ **ของฟรีต้องไม่แพ้ของที่ขาย**

> ข้อมูลฟีเจอร์ของสินค้าหลายตัวมาจากหน้าประกาศขาย ไม่ใช่คู่มือผู้ผลิต และ PID เฉพาะยี่ห้อทั้งหมดมาจากข้อมูลชุมชนออสเตรเลีย
> **ยังไม่ได้ทดสอบกับ ECU รถสเปกไทย** — ต้องลองกับรถจริงก่อนเชื่อ

## มีแล้ว ✅

- อ่านค่า mode 01 ~80 ค่า ซ่อนค่าที่รถไม่รองรับเอง
- หน้า RACE / DIGITAL / tach + 6 ค่า / กริดทุกค่า / DTC (stored + pending) — หน้าปัดเข็ม (CLUSTER) ถอดออกแล้ว
- **หน้าปัดสไตล์มอเตอร์ไซค์ 2 หน้า** SCOOTER (LCD ฟ้าอมเขียว) + BLUE LCD (km/L เฉลี่ยจาก MAF, เวลาเครื่องติด, ป้าย CHECK) — ไม่มี RTC จึงยังไม่มีนาฬิกาจริง
- shift light (RACE + DIGITAL)
- **หน้า NAV (ต้นแบบ)** ลูกศรเลี้ยว/ระยะ/ถนน/ETA จากมือถือทาง BLE ขณะยังต่อ ELM327 อยู่ + บอกจุดเลี้ยวบนแถบสถานะทุกหน้า — ดูหัวข้อนำทางด้านล่าง
- **บูสต์ + ค้างค่าสูงสุด** บน RACE และ DIGITAL (กดค้างที่ช่อง BOOST = รีเซ็ต)
- **เตือนต่ำ/สูงทุก PID** hysteresis 1 วิ, การ์ด/ตัวเลขกระพริบแดง + แถบสถานะแดงทุกหน้า, เกณฑ์เก็บ NVS (ตั้งผ่าน serial `L`)
- **Trip computer A/B** ระยะทาง เวลาขับ ความเร็วเฉลี่ย/สูงสุด เวลาเดินเบา เก็บ NVS
- **จับเวลา 0–100 / เบรก 100–0** พร้อม +/- ความแม่นยำ และระยะเบรก
- **หน้า HEALTH เตือนล่วงหน้า** ไฟชาร์จ, fuel trim, วาล์วน้ำ, แคต (O2 หลังตามหน้า), DTC — เทียบกับ baseline ของรถคันนั้น เก็บประวัติ 32 ทริปใน NVS (ยังไม่ได้ทดสอบกับรถจริง)
- **หน้า SERVICE: relearn ปีกผีเสื้อหลังล้าง** เลือกยี่ห้อ (Nissan, Honda เก่า/ใหม่, Toyota, Mazda, ดีเซล) → ทำทีละขั้น ชิปเงื่อนไขจากค่าสด + ตัวจับเวลา/จังหวะกุญแจ-คันเร่ง — ไม่ส่งคำสั่งเข้า ECU, ป้ายบอกความน่าเชื่อของแหล่งที่มา (ยังไม่ได้ทดสอบกับรถจริง)
- องศาจุดระเบิด (PID 0E), โหมด demo, 60 fps, OBD แยกคอร์
- ภาพหน้าจอผ่าน USB (`tools/screenshot.py`)

## นำทาง Google Maps บนเกจ 🧭 (ต้นแบบ — หน้า NAV)

**คำถามจากเจ้าของ:** โชว์ลูกศรเลี้ยว / แผนที่เล็กจาก Google Maps ได้ไหม และต่อบลูทูธ 2 อย่าง (dongle OBD + มือถือ) พร้อมกันได้ไหม
**สรุป:** ลูกศร + ระยะทาง + ชื่อถนน + ETA **ได้** (ทำต้นแบบแล้ว) · แผนที่สด **ไม่ทำ** · Android ใช้ได้จริง, iPhone ยังไม่แน่

### 1. บลูทูธ 2 การเชื่อมต่อพร้อมกัน — ได้

- core 3.3.10 ที่เราใช้ **ไม่ใช่ Bluedroid แล้ว** — ไลบรารี `BLEDevice` รันบน **NimBLE** (ตรวจจาก `esp32s3-libs/3.3.10/sdkconfig`: `CONFIG_BT_NIMBLE_ENABLED=y`, `CONFIG_BT_NIMBLE_MAX_CONNECTIONS=3`, `CONFIG_BT_CTRL_BLE_MAX_ACT=6`)
  ([release 3.3.0](https://github.com/espressif/arduino-esp32/releases/tag/3.3.0))
- เกจเป็น **client** ของ ELM327 และเป็น **server** ให้มือถือพร้อมกันได้ — core มีตัวอย่าง `Client_Server` ทดสอบแล้วทั้ง NimBLE/Bluedroid ([PR #12141](https://github.com/espressif/arduino-esp32/pull/12141))
- ใช้ 2 จาก 3 การเชื่อมต่อ + advertising + scan = 4 จาก 6 "activity" ของ controller — ยังเหลือ
- **RAM ภายในคือข้อจำกัดจริง:** ตอนแรกหน้าจอทุกหน้าจอง sprite ใน RAM ภายในจนเหลือ ~7 KB → มือถือต่อแล้ว `BLE_INIT: Malloc failed`
  แก้ด้วยการกัน 32 KB ไว้ตอนสร้าง sprite (`BLE_HEAP_RESERVE`) sprite ที่ไม่พอจะไปอยู่ PSRAM เอง → เหลือ ~37 KB (ต่ำสุด 13 KB) ตอนมือถือต่ออยู่
- **วัดจริง (PC แทนมือถือ, `tools/nav_send.py`):** ต่อได้ใน ~2 วิ, MTU 256, เขียนหนึ่งครั้ง median 120 ms (p95 124 ms), ยิงต่อเนื่องได้ ~8 ครั้ง/วิ,
  จอยัง 62 fps ทุกหน้า, เกจยังสแกนหา ELM327 ต่อไประหว่างที่มือถือต่ออยู่
- **ความเร็ว OBD:** วิทยุตัวเดียวแบ่งเวลาให้สองลิงก์ มือถือส่งแค่ ~1 ครั้ง/วิ (< 100 ไบต์) จึงคาดว่ากระทบน้อย — **ยังไม่ได้วัดกับ dongle จริง** (ไม่มี dongle ตอนทดสอบ)

### 2. มือถือส่งข้อมูลมายังไง

Google **ไม่มี API** ให้แอปอื่นอ่านเส้นทางของแอป Google Maps (ช่องทางทางการมีแค่ Android Auto และ Navigation SDK แบบเสียเงินที่ต้องฝังในแอปตัวเอง)
วิธีที่ทุกโปรเจกต์ใช้คือ **อ่านการแจ้งเตือนนำทาง** ของ Google Maps (`NotificationListenerService` บน Android) แล้วส่งต่อทาง BLE
— เป็นพื้นที่สีเทาตามเงื่อนไขของ Google: ทำเป็นของใช้ส่วนตัว ไม่ใช่ฟีเจอร์ "รองรับ Google Maps อย่างเป็นทางการ"

| ทางเลือก (Android) | ไลเซนส์ | ส่งอะไร | ใช้กับเราได้ไหม |
|---|---|---|---|
| แอป **Chronos** + ไลบรารี ChronosESP32 (fbiego) | แอป: ปิดซอร์ส มีโฆษณา ห้ามดัดแปลง / ไลบรารี: MIT | ระยะ, เวลา, ETA, ทิศ, ชื่อถนน + ไอคอน 48×48 1-bit | ใช้แอปได้เลย แต่ไลบรารีจะยึด BLE ทั้งหมด (ชนกับ ELM327) → ต้องเขียนโปรโตคอลเล็ก ๆ ของมันใหม่บน `BLEServer` ของเรา; ต้องทำตัวเป็น "นาฬิกา" |
| [Gadgetbridge](https://codeberg.org/Freeyourgadget/Gadgetbridge) | AGPL-3.0 | parse การแจ้งเตือนนำทาง (ต้องปิด "Live Updates" ของ Maps) | อ้างอิงได้ — ส่วนที่หยิบมายังเป็น AGPL |
| GMapsParser | LGPL-3.0 | parser Kotlin สำหรับการแจ้งเตือน Maps (อัปเดตล่าสุด 2023) | **ฐานที่ดีที่สุดสำหรับแอปของเราเอง** |
| CarPlayBLE | GPL-3.0 | แอป Android + จอ ESP32 แสดงนำทาง Maps | อ้างอิง/หยิบโค้ดได้ (เราเป็น GPL-3.0 แล้ว) |

**iPhone:** ช่องทางเดียวคือ ANCS (Apple ให้อุปกรณ์อ่านการแจ้งเตือน) ได้แค่ **ข้อความ** (ชื่อแอป หัวเรื่อง ข้อความ) ไม่มีไอคอน
และ Google Maps บน iOS แสดงนำทางเป็น **Live Activity** บนหน้าล็อก ซึ่ง *น่าจะ* ไม่ผ่าน ANCS → **อาจไม่ได้อะไรเลย ต้องลองกับเครื่องจริง** iOS ไม่มี API อื่นให้ดึงข้อมูลนำทางของแอปอื่น
ฝั่งเกจเตรียมไว้แล้ว: ถ้าส่งแค่ข้อความ ("Turn left onto ...") เกจเดาทิศจากคำในข้อความเอง

### 3. แผนที่เล็กแบบสด — ไม่ทำ

- **เงื่อนไข Google:** ห้ามดึงล่วงหน้า/แคช/ดาวน์โหลดภาพแผนที่ (Maps Platform Terms 3.2.3 a/b) และห้ามใช้ในอุปกรณ์ที่ติดตั้งในรถ (3.2.3 f)
- **แบนด์วิดท์:** BLE ของ S3 ส่งได้จริงราว 46 KB/s ([esp32.com](https://esp32.com/viewtopic.php?p=134183)) ภาพสีหนึ่งช่องใช้ ~1 วิ และกินวิทยุที่ต้องแบ่งกับ ELM327
- **ไม่มี GPS บนบอร์ด** — ตำแหน่ง/ทิศต้องมาจากมือถืออยู่ดี
- ทางเลือกในอนาคต: แผนที่ OpenStreetMap (ODbL) แบบ vector บน SD + GPS — งานใหญ่ ไม่เกี่ยวกับ Google

### ต้นแบบที่ทำแล้ว (`nav.h`, หน้า NAV)

- GATT service `5a4e0001-…` ข้อความ `N|<turn>|<เมตร>|<eta>|<ถนน>` หรือ `X` (จบ) + ช่องไอคอน 48×48 1-bit (รูปแบบเดียวกับ Chronos) — รายละเอียดใน [03-architecture.md](03-architecture.md)
- หน้า NAV: ลูกศรใหญ่ (วาดเอง 10 แบบ หรือไอคอนจากมือถือขยาย 3×), ระยะ, ชื่อถนน, ETA, ความเร็ว
- **ระยะนับถอยหลังด้วยความเร็ว OBD** ระหว่างที่มือถือยังไม่ส่งค่าใหม่ → ตัวเลขลดลื่น ๆ
- หน้าอื่น: เหลือ ≤ 1 กม. ถึงจุดเลี้ยว แถบสถานะขึ้น `LEFT in 300 m` สีฟ้า (alarm ยังสำคัญกว่า)
- โหมด demo มีเส้นทางจำลอง, ทดสอบจาก PC ด้วย `python tools/nav_send.py` (bleak) หรือ serial `VN|left|300|14:32|Rama IV Rd`
- จอไม่มีฟอนต์ไทย → ชื่อถนนภาษาไทยจะหายไป (เหลือแค่ลูกศร + ระยะ) ตั้งภาษา Google Maps เป็นอังกฤษถ้าอยากเห็นชื่อถนน

**ขั้นต่อไป:** (1) ทดสอบกับ dongle จริง วัดอัตราอ่าน PID ตอนมือถือต่ออยู่/ไม่ต่อ (2) แอป Android เล็ก ๆ ของเราเอง (GPL-3.0) ต่อยอดจาก GMapsParser/CarPlayBLE (3) ทดลอง ANCS กับ iPhone จริง (4) ถ้าจะเข้ากับแอป Chronos: เขียนโปรโตคอล Chronos ซ้ำบน server ของเรา (5) จับคู่/ผูก (bonding) กันคนอื่นส่งข้อความมาที่จอ

| **โลโก้/ภาพบูต/ธีม** | เปลี่ยนรูปกลางหน้าปัดได้ (ของที่ขายมีฟีเจอร์นี้) |
| **ประวัติการเผา DPF** | 10 ครั้งล่าสุด ระยะทางระหว่างครั้ง |
| **อัปเดตเฟิร์มแวร์จาก SD** | วางไฟล์ `.bin` แล้วบูต |

## ดีไซน์ที่จะทำต่อ 🎨

จากการสำรวจหน้าปัด Lamborghini (Strada/Sport/Corsa), Ferrari, McLaren (Slim mode), Porsche (Pure), AiM/MoTeC/Haltech:

| ไอเดีย | รายละเอียด |

| **ธีมตามโหมดขับ** | Strada ขาว/ฟ้า · Sport อำพัน `#FFB000` · Corsa เขียว→เหลือง→แดง · Rosa ชมพู `#FF4FA0`→ม่วง `#9B5CFF` · Night ดำล้วน ไฟหรี่ — pre-render พื้นหลังต่อธีมใน PSRAM (8 MB พอหลายธีม) เปลี่ยนด้วย wipe 150–250 ms |
| **หน้า Corsa (สนาม)** | tach เป็นแถบแนวนอนเต็มจอด้านบน 32 ช่อง, เลขเกียร์ใหญ่กลางจอ ≥ 96 px, การ์ดซ้ายขวามีค่าสูงสุดตัวเล็กใต้ค่า |

| **แถบ shift light** | เขียว ×4 → อำพัน ×4 → แดง ×4, ถึงลิมิตกระพริบทั้งแถบ ~8 Hz |
| **เทคนิคหรู** | สร้างภาพ "ติด" และ "ดับ" ของหน้าปัดไว้ทั้งคู่ แล้วคัดลอกเฉพาะส่วนลิ่มระหว่างมุมเก่า-ใหม่ (ได้ arc ไล่สี+glow แทบฟรี), เงาเข็ม (trail) 3–4 เฟรมจาง ๆ, dithering 4×4 Bayer กันสีเป็นแถบบน gradient ชมพู, ตัวเลขความเร็วอัปเดต 8–10 Hz อ่านง่ายกว่า |

## ฮาร์ดแวร์เสริม (ไอเดีย)

- บัซเซอร์ / ลำโพง I2S สำหรับเตือน
- LDR ปรับแสงอัตโนมัติ
- IMU (I2C) วัดแรง G จริงด้านข้าง/หน้า-หลัง
- GPS (UART) จับเวลารอบสนาม
- TPMS 433 MHz
- ต่อ CAN ตรง (TWAI) ไม่ผ่าน ELM327 — เร็วกว่ามาก แต่ต้องมีวงจร transceiver
