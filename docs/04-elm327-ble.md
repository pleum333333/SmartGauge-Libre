# 04 · ELM327 ผ่าน Bluetooth LE

โค้ดอยู่ใน [`elm327_ble.h`](../OBD_Dashboard/elm327_ble.h) — ใช้ไลบรารี BLE ที่มากับ Arduino-ESP32 (Bluedroid)

## 1. หา dongle

`scanAndConnect()` สแกน 5 วินาที (active scan) แล้วเลือกตัวที่ **RSSI แรงที่สุด** ในบรรดาตัวที่เข้าเงื่อนไข:

- ชื่อ (ตัวพิมพ์เล็ก) มีคำว่า `obd elm vlink v-link vlinker vgate icar konnwei veepeak carista`
- หรือประกาศ service `0xFFF0`, `0xFFE0`, `0x18F0`

ทุกอุปกรณ์ที่สแกนเจอจะพิมพ์ใน Serial พร้อมเครื่องหมาย `<- OBD?` ตรงตัวที่เข้าเงื่อนไข
ถ้า dongle ของคุณไม่ถูกเลือก ให้ดูชื่อ/MAC จาก log แล้วตั้ง:

```cpp
#define OBD_DEVICE_NAME "IOS-Vlink"   // หรือ "aa:bb:cc:dd:ee:ff"
```

ไว้ **ก่อน** `#include "elm327_ble.h"`

## 2. หา "สาย UART" ใน GATT

dongle BLE แต่ละยี่ห้อใช้ UUID ไม่เหมือนกัน ที่เจอบ่อย:

| Service | RX (notify) | TX (write) | พบใน |
|---|---|---|---|
| FFF0 | FFF1 | FFF2 | Vgate iCar Pro BLE, vLinker, ตัวจีนทั่วไป |
| FFE0 | FFE1 | FFE1 (ตัวเดียวกัน) | โมดูล HM-10 / CC2541 |
| 18F0 | 2AF0 | 2AF1 | OBDLink CX, บางรุ่น |

แทนที่จะ hard-code เราใช้ `findUart()`: ไล่ทุก service (ข้าม 1800/1801/180A ที่เป็น standard)
แล้วเลือก service แรกที่มีทั้ง characteristic ที่ **notify/indicate ได้** และที่ **write ได้** — ใช้ได้กับทั้ง 3 แบบโดยไม่ต้องแก้โค้ด

- ข้อมูลขาเข้า: callback `elmNotify` ใส่ลง FreeRTOS **stream buffer** 2 KB (callback รันใน BT task)
- ข้อมูลขาออก: เขียนแบบ write-without-response ถ้าทำได้ (เร็วกว่า) ไม่งั้น write-with-response

## 3. โปรโตคอล ELM327

ELM327 คือ "โมเด็ม" ที่แปลงคำสั่งข้อความ ASCII ↔ บัส OBD ของรถ (CAN, ISO 9141, KWP2000, J1850)
ทุกคำสั่งจบด้วย `\r` และ ELM ตอบกลับจบด้วย prompt `>` → `command()` อ่านจนเจอ `>` หรือหมดเวลา

ลำดับ init (`initAdapter()`):

| คำสั่ง | ความหมาย |
|---|---|
| `ATZ` | รีเซ็ต (ตอบเวอร์ชัน เช่น `ELM327 v1.5` — ตัวก๊อปส่วนใหญ่อ้างเวอร์ชันนี้) |
| `ATE0` | ปิด echo |
| `ATL0` | ปิด linefeed |
| `ATS0` | ปิดช่องว่างระหว่างไบต์ → `410C1AF8` แทน `41 0C 1A F8` |
| `ATH0` | ปิด header (ไม่แสดง ID ของ ECU) |
| `ATAT1` | adaptive timing (ELM เดาเวลารอเอง) |
| `ATSP0` | เลือกโปรโตคอลอัตโนมัติ |

จากนั้น `connectEcu()`:

| คำสั่ง | ความหมาย |
|---|---|
| `0100` | PID ที่รองรับ 01–20 (bitmask 32 บิต) — ครั้งแรกจะเห็น `SEARCHING...` |
| `0120`, `0140`, `0160` | PID 21–40, 41–60, 61–80 (อ่านต่อเฉพาะถ้าบิตสุดท้ายของชุดก่อนหน้าเป็น 1) |
| `ATDP` | ชื่อโปรโตคอล เช่น `ISO 15765-4 (CAN 11/500)` |
| `ATDPN` | เลขโปรโตคอล — `6`–`9`, `A`–`C` = CAN (ใช้ตัดสินวิธีถอด DTC) |

### การอ่าน PID (`queryPid`)

ส่ง `01XX` → คำตอบ `41XX` + ไบต์ข้อมูล (A, B, …)
โค้ดล้างทุกอย่างที่ไม่ใช่ hex ออก แล้วหา `41XX` ในสตริง — ทนต่อ `SEARCHING...`, บรรทัดว่าง, และรถที่มีหลาย ECU ตอบพร้อมกัน
ถ้าได้ `NO DATA`, `?`, `UNABLE TO CONNECT` → คืนค่า `NAN` (บนจอจะเป็น `--`)

### แรงดันแบต

ถ้ารถไม่รองรับ PID `0x42` ใช้ `ATRV` แทน (ELM วัดแรงดันที่ขา 16 ของปลั๊ก OBD เอง ใช้ได้แม้ไม่ได้เปิดสวิตช์กุญแจ)

## 4. Bitmask PID ที่รองรับ

คำตอบ `4100BE3EB813` → ไบต์ `BE 3E B8 13` = 32 บิต
บิตซ้ายสุด (MSB) = PID 0x01, บิตขวาสุด = PID 0x20

```cpp
bank = (pid - 1) / 32;  bit = 31 - ((pid - 1) % 32);
supported = pidMask[bank] & (1u << bit);
```

## 5. ข้อควรรู้/ข้อจำกัด

- ELM327 ตัวก๊อปบางตัวตอบช้า (100–300 ms ต่อคำสั่ง) → อ่านได้ราว 3–10 ค่า/วินาที **รวมทุกค่า**
  นี่คือเหตุผลที่เราอ่านเฉพาะค่าที่อยู่บนหน้าจอ
- ยังไม่ได้ใช้เทคนิคเร่งความเร็ว เช่น ส่งหลาย PID ในคำสั่งเดียว (`010C0D05`, รองรับเฉพาะ CAN)
  หรือเติมจำนวนคำตอบท้ายคำสั่ง (`010C1`) — เป็นงานที่น่าทำต่อ (ดู roadmap)
- ทุกค่าเป็น PID มาตรฐาน SAE J1979 ค่าเฉพาะยี่ห้อ (เช่น อุณหภูมิเกียร์, DPF ของกระบะดีเซล) ต้องใช้ mode 22 + header เฉพาะรุ่น — ยังไม่ทำ
