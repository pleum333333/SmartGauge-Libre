# 07 · UI และประสิทธิภาพ (60 fps)

## ธีม

สีทั้งหมดอยู่ใน `namespace theme` ใน [`ui.h`](../OBD_Dashboard/ui.h) (RGB565 สร้างด้วย `rgb(r,g,b)` ตอนคอมไพล์)

| ชื่อ | ใช้กับ |
|---|---|
| `BG` (4,7,14) | พื้นหลังน้ำเงินเกือบดำ |
| `PANEL` / `EDGE` / `DIM` | การ์ด / ขอบ / ช่องที่ดับ |
| `CYAN` | อากาศ/น้ำมัน, ปุ่ม, จุดหน้าปัจจุบัน |
| `GREEN` | โหลด/คันเร่ง, สถานะเชื่อมต่อ |
| `AMBER` / `ORANGE` / `RED` | ไฟฟ้า, เตือนระดับต่าง ๆ |
| `VIOLET` | ค่าเครื่องยนต์/การจุดระเบิด |

สีไฟเตือนบนหน้าปัดใช้หลักเดียวกับรถจริง (ISO 2575): **แดง = อันตราย หยุด**, **เหลือง/ส้ม = ผิดปกติ ตรวจสอบ**, **เขียว = ข้อมูล**, **ฟ้า = เย็นเกิน**

## ตัวเลขที่วัดจริง (โหมด DEMO วนทุกหน้า)

| | ก่อนปรับ | หลังปรับ |
|---|---|---|
| หน้า tach ต่อเฟรม | 65 ms + `delay(30)` ≈ **10 fps** | 2–4 ms → ล็อก **60 fps** |
| วาดวงรอบ 40 ช่อง | 52 ms | ~1–1.5 ms |
| หน้าปัดซูเปอร์คาร์ | – | 6.5–7.8 ms (แย่สุด 15 ms) → **60 fps** |
| การ์ด 1 ใบ | 2–3 ms (PSRAM) | 1.4–2 ms (RAM ภายใน) |
| เปลี่ยนหน้า | 23–82 ms | ~28 ms |

เพดานจริงคือ **~57 fps** เพราะจอรีเฟรช 56.8 Hz ([01-hardware.md](01-hardware.md)) ตัวเลข FPS โชว์สดบนแถบด้านบน
(เขียว ≥ 50, เหลือง ≥ 30, แดง < 30)

## ทำไมตอนแรกถึงช้า

จอนี้ **ไม่มีชิปไดรเวอร์** — ภาพทั้งจออยู่ใน framebuffer บน **PSRAM** และ DMA อ่านส่งออกจอตลอดเวลา
ทุกพิกเซลที่เราเขียนลง PSRAM แย่งแบนด์วิดท์กับ DMA → เขียน PSRAM ช้ากว่า RAM ภายในมาก
การวาดวงรอบใหม่ทั้งวงทุกเฟรม (40 × `fillArc` ใน sprite บน PSRAM แล้ว push อีก 120 KB) จึงกินเวลา 60 ms

## กฎ 5 ข้อที่ทำให้ได้ 60 fps (ใครแก้ UI ต้องรักษาไว้)

1. **วาดเฉพาะสิ่งที่เปลี่ยน** — ทุกการ์ดจำสตริงที่โชว์อยู่ (`shown[i]`) ถ้าเหมือนเดิมไม่วาด
   วงรอบจำสถานะแต่ละช่อง (`segState[]`) วาดใหม่เฉพาะช่องที่ติด/ดับเปลี่ยน
2. **ของนิ่งเรนเดอร์ครั้งเดียว** — พื้นหน้าปัด ตัวเลขสเกล ขีด ป้าย อยู่ใน sprite บน PSRAM สร้างตอนบูต
   ตอนเปลี่ยนหน้าแค่ `pushSprite` ทีเดียว
3. **sprite ที่วาดทุกเฟรมอยู่ RAM ภายใน** (`makeFast()` — ถ้า RAM ไม่พอจะถอยไปใช้ PSRAM เอง)
4. **ประกอบภาพก่อนส่งขึ้นจอ** (หน้าปัดเข็ม `cluster.h`): คำนวณกรอบที่เข็มเก่า+ใหม่ครอบ →
   คัดลอกพื้นหลังส่วนนั้นลง tile 128×128 ใน RAM → วาดตัวเลข+เข็มลง tile → push ขึ้นจอด้วย clip rect
   → **ไม่มีจังหวะที่เข็มหายไป จึงไม่กระพริบ**
5. **ห้ามบล็อกลูป UI** — ไม่มี `delay()` ตายตัว ใช้ `paceFrame()` ล็อก 16 ms ต่อเฟรม,
   งาน OBD อยู่คอร์ 0 ([03-architecture.md](03-architecture.md)), การเคลื่อนไหวคำนวณจาก **เวลาจริง (dt)**
   ไม่ใช่จำนวนเฟรม → ความเร็วเข็มเท่ากันไม่ว่า FPS เท่าไหร่

## หน้าปัดซูเปอร์คาร์ (`cluster.h`)

> ถอดออกจากรอบหน้าแล้ว (ไฟล์ยังอยู่ แต่ไม่ได้ include) — เทคนิคข้างล่างยังใช้อ้างอิงได้

| ส่วน | ตำแหน่ง (พิกัดใน sprite, y เริ่มใต้แถบสถานะ 26 px) |
|---|---|
| หน้าปัดกลาง ความเร็ว 0–260 กวาด 270° | ศูนย์ (240,122) r=100, ไล่สีชมพู→ม่วงจากกลางออกนอก + glow |
| หน้าปัดซ้าย รอบเครื่อง 0–8k กวาดครึ่งซ้าย | ศูนย์ (80,124) r=78 ไล่สีน้ำเงิน |
| หน้าปัดขวา อุณหภูมิน้ำ 40–130 °C กวาดครึ่งขวา | ศูนย์ (400,124) r=78 |
| มุมบนซ้าย / ขวา | องศาจุดระเบิด / น้ำมันเชื้อเพลิง |
| แถวล่างซ้าย | ไฟเตือน: เช็คเอนจิ้น, แบต, ความร้อน |
| แถวล่างขวา | ไฟเตือน: น้ำมันใกล้หมด, น้ำมันเครื่องร้อน, เปลี่ยนเกียร์ (≥ 6500 rpm) |

เข็มด้านข้างตั้งใจให้กวาดแค่ครึ่งนอก เพื่อไม่ให้ทับหน้าปัดกลางที่ซ้อนอยู่
ไอคอนไฟเตือนวาดด้วยรูปทรงพื้นฐาน (สี่เหลี่ยม วงกลม สามเหลี่ยม) ไม่ใช้รูปภาพ — ไม่มีปัญหาลิขสิทธิ์

## ฟอนต์

ใช้ฟอนต์ที่มากับ LovyanGFX: FreeSans / FreeSansBold / FreeSansBoldOblique 9–24pt (จาก Adafruit GFX, GNU FreeFont),
`Font6` (ตัวเลขใหญ่ 48 px), `Font7` (7-segment) — **ไม่มีภาษาไทยและไม่มีสัญลักษณ์ °**

> ⚠️ **ห้ามใช้ `Font2` หรือฟอนต์เส้นบาง 1 พิกเซล** — บนจอจริงของบอร์ดนี้ ตัวอักษรเส้นบางเพี้ยนจนอ่านไม่ออก
> (ในภาพที่ดึงจาก framebuffer ด้วย `tools/screenshot.py` ดูปกติ แต่จอจริงแสดงพิกเซลเดี่ยว ๆ ผิด — ยืนยันจากรูปถ่ายจอจริง)
> ตัวหนังสือเล็กสุดให้ใช้ `FreeSans9pt7b` / `FreeSansBold9pt7b`
> นอกจากนี้ขอบจอจริงถูกกรอบบังไป 2–4 px — อย่าวางตัวหนังสือชิดขอบ (เว้น ≥ 8 px)

## ภาพหน้าจอผ่าน USB

```bash
python tools/screenshot.py COM3 shot.png --cmd D
```

`--cmd` ส่งคำสั่งก่อนถ่าย: `D` = เปิด/ปิด demo, `N`/`P` = หน้าถัดไป/ก่อนหน้า
ใช้ตรวจ layout ได้โดยไม่ต้องถ่ายรูปจอ (แต่ต้องดูจอจริงด้วยเรื่องความคมของฟอนต์ ตามข้อเตือนด้านบน)
ถ้าจะใส่ภาษาไทยบนจอ ต้องแปลงฟอนต์ไทย (เช่น Sarabun / Noto Sans Thai ที่เป็น OFL) เป็น VLW แล้วโหลดจาก SD card
